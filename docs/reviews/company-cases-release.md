# 企業導入事例の公開確認

## 公開範囲

株式会社ワイズマート、株式会社サンケイビルウェルケアの企業導入事例を追加。
提供・公開承認された原稿をもとに、原本ロゴ、企業別カラーのカード、詳細記事、相互リンク、サイトマップを整備した。
既存の匿名事例4件とVOICES5記事は維持する。内部の原資料は公開リポジトリに含めない。

## 確認観点

- 原稿の引用・数値・時系列と掲載文の照合。回答率を定着率として表現しない。
- ロゴの原本との一致、縦横比、見出しの句読点、PCとモバイルの表示。
- カードから詳細記事、関連事例、企業導入事例一覧へ戻る導線。
- canonical、OG画像、CTA、既存記事を含む9URLのサイトマップ。
- 独立レビューで原稿・ロゴ・生成物・公開差分・CIを確認。

## モバイル表示

公開用差分の検証でWebKitモバイルの操作待ちが再現したため、横移動によるはみ出しを抑える既存の修正を含めた。
1024px未満では左右のRevealをフェードのみとし、STORY内の横方向のはみ出しをクリップする。
狭い画面ではフッターリンクを折り返す。PCの左右アニメーション、比較表の横スクロール、メニューは維持する。
画像寸法は表示枠に合わせ、object-fit: containでロゴ比率を保つ。

## 検証と公開手順

`npm run lint`、`npm run build`、`npm run test:layout`を実行する。
回帰テストはChromium/WebKitの計24件。企業記事導線に加え320〜1440pxの幅、メニュー、比較表、ブレークポイントを確認する。
PRの最新head SHAでCI成功とマージ可能状態を確認した後にマージする。
GitHub Pagesのデプロイ成功後、ホームページと企業記事2本の公開URLを確認する。

## 切り戻し

本番で記事・ロゴ・主要導線の欠落や表示崩れが確認された場合、マージコミットをrevertするPRを作成・マージし、Pagesを再デプロイする。
データベース変更はない。前版のホームページと既存VOICESの到達性を確認する。

## ワークフロー記録

依頼されたREADMEのレビュー・独立検証・テスト・リリース判定を、この静的サイトの構成へ適用した。
デザイン改善とモバイル検証の知見は `docs/lessons/company-case-design.yml` に記録した。
他製品固有のデータベース・リリース環境は対象外。

精度記録: ユーザーによるデザイン修正指示1件。独立レビューの必須修正0件。
根本原因の確認は原資料、生成・導線、実ブラウザの3観点で実施。実費・トークン使用量は未計測。
CI・本番結果はPRとGitHub Actionsの当該コミットの記録を正とする。
