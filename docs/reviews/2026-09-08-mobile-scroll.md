# スマホ横揺れ修正の検証記録

成果物種別: コード修正・回帰テスト・検証記録。対象: TalentKeeperの公開LP。

## 適用手順

ユーザー指定のREADMEは本リポジトリに存在せず、/root/project/hrm_project/.claude/skills/README.mdを参照。
フェーズは原因特定済みのバグ修正。impl / orchestrator / review / adversarial-review / releaseの一般手順を適用。
HR Monsterの言語・ブランチ・DB・学習レジストリ等の固有設定は移植しない。
要件・設計はdocs/mobile-scroll-requirements.md、再発防止はdocs/lessons/mobile-scroll-overflow.ymlに保存。

## 変更と影響範囲

- RevealのtransformをCSS変数経由に変更。左右指定の3呼び出し（ヒーロー、STORYの繰り返し、問い合わせフォーム）を1024px未満でフェードのみとする。
- 下方向からのReveal、表示タイミング、IntersectionObserverの解除は従来どおり。
- STORYを横方向にclipし、演出でスクロール領域が広がらないようにする。
- フッターのリンク列を折り返す。
- 表内部のoverflow-x: auto、ナビのsticky、フォーム送信処理は変更しない。
- ブラウザテストと専用PR CIを追加。既存Pagesデプロイワークフローは変更しない。

## 修正前の検証

公開サイトとローカルの既存ビルドで16pxのはみ出しを測定。
先に作成したChromiumテストは8件中6件失敗・2件成功。
失敗は320 / 375 / 390 / 430 / 768pxでの横はみ出しと、スマホの横移動。
320pxにはフッターリンク列の別のはみ出しも存在。

## 自己レビュー・根本原因確認

通常レビュー: 要件、共有Revealの呼び出し、CSS優先順位、幅の境界、依存差分、CI配線を照合。
API・DB・認証・外部連携の変更はない。UIの既存処理を再実装していない。

1. 原因の確認: 公開サイトでSTORYだけを検証ブラウザ内でclipすると390pxの画面で406→390pxになる。bodyの幅制限だけでは子の変形を防げないことを確認。
2. 範囲の確認: 横移動の全呼び出しを確認。STORY以外は親でoverflow hidden。フッターを含めた初期・スクロール時の実測を7画面幅で実施。
3. 副作用の確認: Chromium / WebKitの16件テストが成功。固定ナビ、比較表内部の横スクロール、モバイルメニューを確認。390pxのSTORYとフッターのスクリーンショットを目視確認。

## 検証上の留意点

- npm run build: 成功。
- npm run lint: 既存の未使用features変数1件で失敗。git show HEAD:src/App.jsxを同じeslintに入力して同一エラーを確認済み。今回の変更で増えたエラーではない。
- WebKitはこのUbuntu環境で利用可能な古いビルド。iPhone実機の最新SafariやOSの弾性スクロールそのものを再現した検証ではない。
- ローカルのブラウザテスト実行結果と、GitHub Actions上の結果は区別する。

## 独立レビュー

別コンテキストのエージェントがDeepレビューを実施。実装修正必須の問題なし。
メニューを閉じる側のテスト不足が1件あり、閉状態のmax-height検証を追加。
独立したChromium / WebKit測定でも320 / 390 / 768 / 1024 / 1440pxの初期・STORY・フッターで画面幅とscrollWidthの一致、scrollX=0、ナビ上端=0を確認。

## 最終テスト・トリアージ

画面幅切替の検証を追加した18件の実行は17件成功。WebKitの320pxケースはページ生成時に30秒の起動タイムアウトで失敗。
320pxとメニュー開閉の4件を再実行し、4件成功（22.3秒）。全18ケースに成功結果があるが、18件の単一実行ですべて成功したという意味ではない。
テストは実装の文字列比較ではなく、レンダリング寸法と操作結果を検証する。
実装漏れチェックは要件と各テストを照合し、メニューの閉状態の不足を補完した。
追加のAPI・DB・外部連携レビューは対象外。最新iOS実機での弾性スクロール確認は公開後の確認事項として残す。
